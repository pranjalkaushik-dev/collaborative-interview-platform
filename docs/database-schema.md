# MongoDB Database Design — MVP

This is the team database contract. Stack: **MongoDB Atlas + Mongoose**. Pranjal owns models, validation, indexes, and database access.

## Design rules

- Use MongoDB `_id` / Mongoose `ObjectId` as identifiers.
- Reference a record when it can grow without limit or has its own lifecycle.
- Embed small data which only belongs to its parent document.
- Never send `passwordHash`, hidden test cases, answer keys, or private AI evaluation fields to a candidate.
- Use `createdAt` and `updatedAt` timestamps on every main collection.

## Relationship map

```text
User ─── creates ───> Interview
User ─── appears in ───> Interview.participants[]

Interview ─── has ───> Question ─── embeds ───> testCases[]
Interview ─── has ───> Submission ─── embeds ───> testResults[]
Interview ─── has ───> CodeDocument
Interview ─── has ───> ViolationLog
Interview ─── has ───> AIFeedback
```

## 1. `users`

Authentication and profile data. Do not make separate candidate/interviewer collections.

```js
{
  _id: ObjectId,
  fullName: String,                 // required, 2–80 characters
  email: String,                    // required, lowercase, unique
  passwordHash: String,             // required; bcrypt hash only
  accountRole: 'CANDIDATE' | 'INTERVIEWER',
  avatarUrl: String | null,
  isActive: Boolean,                // default true
  createdAt: Date,
  updatedAt: Date
}
```

Index: `{ email: 1 }` unique.

## 2. `interviews`

The main interview-room document. Participants are embedded because their count is small and they only belong to this interview.

```js
{
  _id: ObjectId,
  title: String,                    // required, 3–120 characters
  description: String,
  createdBy: ObjectId,              // ref: users; interviewer/creator
  interviewType: 'CODING' | 'TECHNICAL' | 'HR' | 'MIXED',
  scheduledAt: Date,
  durationMinutes: Number,          // 15–180
  status: 'DRAFT' | 'SCHEDULED' | 'LIVE' | 'COMPLETED' | 'CANCELLED',
  participants: [{
    user: ObjectId,                 // ref: users
    role: 'INTERVIEWER' | 'CANDIDATE',
    inviteStatus: 'INVITED' | 'JOINED' | 'DECLINED' | 'LEFT',
    joinedAt: Date | null,
    leftAt: Date | null
  }],
  settings: {
    requireFullscreen: Boolean,     // default true
    allowCopyPaste: Boolean,        // default false
    enableCameraPrototype: Boolean, // default false
    maxViolations: Number           // default 3
  },
  startedAt: Date | null,
  completedAt: Date | null,
  createdAt: Date,
  updatedAt: Date
}
```

Indexes: `{ createdBy: 1, scheduledAt: -1 }`, `{ 'participants.user': 1 }`, `{ status: 1, scheduledAt: 1 }`.

## 3. `questions`

One question is one document. Questions are separate because AI/manual creation and ordering change independently.

```js
{
  _id: ObjectId,
  interview: ObjectId,              // ref: interviews; required
  createdBy: ObjectId | null,       // ref: users; null when generated by AI
  source: 'MANUAL' | 'AI',
  type: 'CODING' | 'MCQ' | 'TEXT',
  prompt: String,                   // required
  topic: String,
  difficulty: 'EASY' | 'MEDIUM' | 'HARD',
  order: Number,                    // display order, starting at 1
  coding: {                          // only for type CODING
    supportedLanguages: [String],
    starterCode: Map<String, String>,
    functionName: String | null
  },
  options: [String],                // only for type MCQ
  correctOptionIndex: Number | null, // server-only; never expose to candidate
  expectedKeywords: [String],       // optional TEXT evaluation aid; server-only
  testCases: [{                      // only for type CODING; embedded
    input: String,
    expectedOutput: String,
    visibility: 'PUBLIC' | 'HIDDEN',
    weight: Number
  }],
  createdAt: Date,
  updatedAt: Date
}
```

Index: `{ interview: 1, order: 1 }` unique. Backend must remove hidden tests, `correctOptionIndex`, and `expectedKeywords` before returning a question to a candidate.

## 4. `submissions`

Separate collection because candidates may run/submit code many times. Test results are embedded because they belong to one submission.

```js
{
  _id: ObjectId,
  interview: ObjectId,              // ref: interviews
  question: ObjectId,               // ref: questions
  candidate: ObjectId,              // ref: users
  language: String,
  sourceCode: String,
  action: 'RUN' | 'SUBMIT',
  status: 'QUEUED' | 'RUNNING' | 'COMPLETED' | 'FAILED',
  testResults: [{
    testCaseIndex: Number,
    passed: Boolean,
    actualOutput: String,
    executionTimeMs: Number,
    error: String | null
  }],
  score: Number,
  submittedAt: Date,
  createdAt: Date,
  updatedAt: Date
}
```

Indexes: `{ interview: 1, candidate: 1, createdAt: -1 }`, `{ question: 1, candidate: 1 }`.

## 5. `codeDocuments`

Nitesh’s Socket.IO module uses this to restore a live editor after refresh/disconnect. Save updates with debouncing, not on every keystroke.

```js
{
  _id: ObjectId,
  interview: ObjectId,              // ref: interviews
  question: ObjectId,               // ref: questions
  candidate: ObjectId,              // ref: users
  language: String,
  sourceCode: String,
  version: Number,                  // increment per saved update
  updatedBy: ObjectId,              // ref: users
  createdAt: Date,
  updatedAt: Date
}
```

Index: `{ interview: 1, question: 1, candidate: 1 }` unique.

## 6. `violationLogs`

Rishav’s browser monitoring/proctoring prototype writes one document per important event. Do not store raw camera video in the MVP.

```js
{
  _id: ObjectId,
  interview: ObjectId,              // ref: interviews
  candidate: ObjectId,              // ref: users
  type: 'TAB_HIDDEN' | 'FULLSCREEN_EXIT' | 'COPY' | 'PASTE' |
        'CAMERA_OFF' | 'MIC_OFF' | 'OTHER',
  metadata: Mixed,                  // small safe details only
  occurredAt: Date,
  createdAt: Date
}
```

Index: `{ interview: 1, candidate: 1, occurredAt: -1 }`.

## 7. `aiFeedback`

Rishav creates feedback after an interview; backend stores it and exposes it only to authorized participants.

```js
{
  _id: ObjectId,
  interview: ObjectId,              // ref: interviews
  candidate: ObjectId,              // ref: users
  generatedBy: 'AI',
  summary: String,
  strengths: [String],
  improvements: [String],
  technicalScore: Number | null,    // 0–100
  communicationScore: Number | null,// 0–100
  recommendation: 'STRONG_HIRE' | 'HIRE' | 'MAYBE' | 'NO_HIRE' | null,
  createdAt: Date,
  updatedAt: Date
}
```

Index: `{ interview: 1, candidate: 1 }` unique.

## Not stored in the MVP

- Plain passwords or JWTs
- Raw camera/video recordings
- A separate `results` collection (results are calculated from submissions, violation logs, and AI feedback)
- Socket.IO keystroke history
